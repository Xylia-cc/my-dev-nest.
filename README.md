# 分仓组装量计算器

一张 Excel（BOM关系 / 需求 / 库存 三个工作表）导入即算：
各仓各父件可组装套数、实际消耗明细、库存消耗、各父件 slot 容量，可导出 CSV / XLSX。

## 在线使用

- **GitHub Pages**：https://<账号>.github.io/<仓库>/ （发版自动同步）
- **离线单文件版**：`分仓组装量计算器-离线版.html`（零外部依赖，双击即开，可直接转发）

## 使用步骤

1. 打开页面 → 选择 Excel（含三个工作表）
2. 点「解析并计算」→ 结果区出现
3. 需要留档时点「导出 CSV」或「导出 XLSX」

> 打开页面不会自动出结果 —— 必须导入文件并点击计算。

## 输入格式

| 工作表 | 列 | 说明 |
|---|---|---|
| **BOM关系** | 父件, 子件, [配比], [替换组], [备注], [关系类别] | 父件级展开，各仓共用；**不需要仓库列** |
| **需求** | 父件, 仓库, 需求, [销量], [关系类别] | 销量用于共享料优先级，缺省 0 |
| **库存** | 子件, 仓库, 库存 | 每个仓库只能用自己的料 |

- 工作表名只需含 `BOM关系` / `需求` / `库存` 关键字即可自动匹配
- BOM 列序支持「父件\|子件\|配比」和「父件\|配比\|子件」两种（表头跟着换，或只换数据自动识别）

### 关键口径

- **配比对应**：同一行里，`子件`列那个料配比取 `配比` 列；`替换组`列那个料（主件）配比取 `备注` 的「换配比:N」（未显式列出时按此隐式加入，无备注默认 1）
- **替代规则**：同组子件互为替代，先扣替代件、用尽再扣主件；各子件按「自身库存÷自身配比」分别折算套数后相加（碎片不能互相凑套）
- **碎片处理**：不足一套的碎片不使用、不消耗库存、不展示明细
- **共享子件**：同仓内按「子件销量 = 父件日均 × 配比」降序分配给各父件
- **齐套才成套装**：所有子件×配比都满足才算 1 套，按需求封顶
- **关系标签**：消耗明细按 `关系1 / 关系3 / 关系2` 分批展示，同一标签下不混用替代件与主件

## 开发

```bash
npm install          # 安装 xlsx
npm test             # 回归测试（4 项）
npm run build        # 构建静态站点到 site/
```

代码：`assembly_calculator/engine.js`（核心引擎）、`assembly_calculator/index.html`（页面）

## 发布到 GitHub Pages（发版自动同步）

一次性配置：

```bash
git config --global user.name  "你的名字"
git config --global user.email "你的邮箱"
git remote add origin https://github.com/<账号>/<仓库>.git
```

然后在仓库 **Settings → Pages → Source** 选 `GitHub Actions`。

每次发版：

```bash
bash publish_gh.sh
```

脚本会构建 → 提交 → 推送到 `main`，GitHub Actions 自动完成部署，地址永久不变。

## ⚠️ 单文件版构建铁律

第三方库（xlsx）源码含 `'<html>...<body>'`、`"</body></html>"` 等 HTML 标签字面量。
内联进 `<script>` 时若不处理，浏览器会提前结束 head/body，导致页面脚本不执行。

正确做法（见 `publish/build_gh.js`）：

1. 库源码包成 **JSON 字符串字面量**，所有 `<` 转成 `\u003c`
2. 运行时 `eval()` 执行（**不要套 `JSON.parse`** —— `JSON.stringify` 的结果已是 JS 字符串字面量）
3. 内联替换必须用**函数形式** `html.replace(tag, function(){return rep;})` —— 替换串含 `$` 会被当作特殊模式，导致字符串指数膨胀、进程被 OOM 杀掉
