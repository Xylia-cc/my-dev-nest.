### 现象

### 根因（引擎 Bug）
`G:1717751`（替代件 `1744181` / 主件 `1717751`）在 a-us-cj：
- 替代件库存 **1944**（容量 1944，只被本父件使用 → 非共享）
- 主件库存 **0**（但被 15 个父件共享）

各替换组容量：`G:1698987`=5、`G:1717751`=1944、`G:1730674`=58、`G:1720158`=48、`G:1695280`=2、`G:1752598`=2
→ `rel1Sets=2`（min）、`altMaxSets=5`（容量>rel1 的组中最小）
→ 批次划分：关系1=2套、关系3=3套、关系2=15套

**问题代码**（engine.js 批次2）：
```js
// 改前：批次2 硬编码「纯主件」
var priUsed2 = sets2 * priRatio;
```
隐含假设「批次2 时所有组替代件都已耗尽」。但 `altMaxSets` 只取**容量>rel1 的组中最小值**，
容量远大于该最小值的组（如 G:1717751 容量 1944）在批次2 里替代件**仍有大量剩余**，
却被强制走主件；而主件库存=0 → `consumePrimary` 按可用量裁剪为 0 → **整组在明细中消失**。

### 修复（用户确认口径：每组先用自己替代件，不够再主件）
1. 批次2 计算改为：先 `consumeAlts(sets2)` 用本组替代件，剩余部分才用主件
   ```js
   var altUsed2 = consumeAlts(sets2);
   var altSets2 = altUsed2.reduce((s,u)=>s+u.setsCovered,0);
   var priUsed2 = Math.max(0, sets2 - altSets2) * priRatio;
   ```
2. 新增「批次2 替代件」明细输出（此前只有关系1/3 有替代件输出）
3. 库存扣减改为 `altUsed1.concat(altUsed3).concat(altUsed2)`
