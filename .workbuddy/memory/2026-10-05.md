## 修复：需求解析覆盖 bug（同一父件-仓库多行需求互相覆盖）

### 问题现象
用户用模板 `组装量计算模板-c.xlsx` 测试，对比截图发现 `a-ca-jm 1064109` 结果不符：
- **引擎结果**：供应商子件需求=0/组装=50，单一子件需求=50/组装=0
- **截图期望**：供应商子件需求=50/组装=50，单一子件需求=200/组装=200

### 根因分析
需求表数据：
- 行1：1064109 | a-ca-jm | **200** | 1.428... | 单一子件
- 行2：1064109 | a-ca-jm | **50** | 2.5 | 供应商子件

引擎 `demandInfo` 使用 `Map<wh, demand>`，同一(父件,仓库)的多个需求行互相覆盖：
- 行1 先 set：demandByWh['a-ca-jm'] = 200
- 行2 后 set：**覆盖**为 demandByWh['a-ca-jm'] = 50

后果：单一子件的 200 需求丢失，只剩 50。

同时引擎逻辑：
1. `displayDemand`：当有 single 组时 supplier 显示 0 → 供应商子件需求显示 0
2. `effectiveDemand = totalDemand - supplierAssembled` → 单一组封顶 = 50 - 50 = 0

### 修复内容
1. **需求解析**：增加 `demandByWhCat` 按(仓库,关系类别)分别存储，同时 `demandByWh` 改为**累加总需求**
2. **实例发现**：判断是否有多个类别的需求行
   - `hasMultiCat=true`：按类别分别驱动，每个实例用自己的需求值，无需求则跳过
   - `hasMultiCat=false`：保持旧逻辑（单行作为总需求分配给所有 BOM 组）
3. **封顶逻辑**：多行需求时各组独立封顶（`independentCap=true`），不受供应商组已组装量影响
4. **瓶颈文本**：多行需求时不显示"供应商已组X套后有效需求"

### 修复后结果
- `1064109 a-ca-jm`：
  - 供应商子件：需求 **50**，组装 **50** ✅
  - 单一子件：需求 **200**，组装 **200** ✅

## 修复：替换组非共享子件可用库存被当作 0（1621249 组装量为 0）

### 问题现象
用户用模板 `组装量计算模板.xlsx`（BOM 20193行/需求 933行/库存 44842行）测试，`a-us-ty 1621249` 组装量为 0。
瓶颈提示自相矛盾："瓶颈=1694191(可组953套 < 需求950)"（953 > 950 却组装 0）。

### 根因分析
1621249 有一个替换组 `G:1683846`：
- 替代件 **1694228**：不共享（仅 1 个父件），a-us-ty 库存 **7056** → 容量 3528 套，**完全够 950 套**
- 主件 **1683846**：共享（13 个父件），a-us-ty **无库存记录（=0）**

我之前（2026-09-30）修复的 Phase 3 替换组合并逻辑有缺陷：
```js
slot.children.forEach(function (c) {
  totalAllocated += t.allocated.get(c.child) || 0;  // 只累加 allocated
});
```
**非共享子件（1694228）在 Phase 2 不进 allocated（Phase 4 才从 pool 扣），其可用库存被错误当作 0。**
→ totalAllocated = 0（替代件）+ 0（主件无库存）= 0 → maxSets = 0 → k_actual = 0。

### 修复内容
Phase 3 与 Phase 3.5 步骤 3 的替换组合并逻辑，按子件类型分别取可用量：
- **共享子件**：取 `t.allocated`
- **非共享子件**：取 `pool` 当前库存（尚未扣减）

### 修复后结果
- `1621249 a-us-ty`：组装量 **0 → 950**（齐套满足）
- 消耗明细：替代件 1694228 消耗 1900（950套×配比2），其余 12 个子件各 1900
- 完整性校验：3019 个子件，**0 个超库存扣减**
