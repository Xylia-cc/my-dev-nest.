## ⚠️ 需求②：单文件离线版存在严重缺陷（本次新发现并修复）

### 现象
昨天发布的「单文件离线版」**页面脚本根本不执行** —— 用户拿到后完全不能用。

### 根因（关键认知）
xlsx 库源码里含 **HTML 标签字面量**：
```js
var Bm='<html><head><meta charset="utf-8"/><title>SheetJS Table Export</title></head><body>';
var Wm="</body></html>";
```
浏览器在 `<script>` 内虽认 `</script` 为脚本结束，但遇到 `</body>` / `</head>` / `<body>` 会**提前结束 head/body**，
导致后续 14 万字符的页面内容结构错乱、业务脚本不执行（`typeof XLSX === undefined`）。
- 之前"验证通过"是假象：那次用的是 `dist/single-file.html`，恰好不含该问题。

### 修复方案（publish/build6.js）
把库源码包成 **JSON 字符串字面量**，所有 `<` 转成 `<`，运行时 `eval()` 执行：
```js
function toSafeJsonLiteral(js){ return JSON.stringify(js).replace(/</g, '\\u003c'); }
// <script data-inlined="xlsx.full.min.js">
//   eval("...转义后的库源码...");
// </script>
```
- HTML 解析器完全看不到任何标签 ✅
- `eval` 让库代码**真正执行**（`window.XLSX` 正常挂载）✅
- ⚠️ **不要写 `JSON.parse(...)`**：`JSON.stringify` 的结果已经是「一个 JS 字符串字面量」，再套 JSON.parse 会把库源码当 JSON 文本解析 → `Unexpected token '/'`。
- engine.js / sample_data.js 直接内联（自研代码无标签字面量），并把 `</` 转义为 `<\/`、`<!--` 转义为 `<\!--` 保险。

### 修复后验证（Chrome headless，`file://` 双击场景）

|---|---|
| `typeof XLSX` | object ✅ |
| `XLSX.read` 可用 | true ✅ |
| 刚打开结果区 | HIDDEN ✅ |
| 引擎自测 assembled | 10（应为10）✅ |
| 端到端（迷你模板）：选文件→点计算 | 结果区 SHOWN、总需求10/总组装10/齐套率100%、明细2行、slot3行 ✅ |
