## 修复：批次3 边界导致「同一替换组内替代件+主件混用」+ 主件超扣

### 用户提问
模板 `组装量计算模板261020.xlsx`：`a-us-cj 1743969` 下关系3 为何出现 `1744194`（替代件）+ `1752598`（主件）子件混用？

### 根因 1：批次3 右边界取「最大值」→ 容量居中的组组内混用
旧算法 `altMaxSets = max(所有组容量) = 34` → sets3 = 34−2 = 32。
但 `G:1752598` 容量仅 32，在批次1 已用 2 套后只剩 **30**，凑不满 32 套 → 其中 2 套被迫转主件 1752598。
于是关系3 内出现「替代件 30 套 + 主件 2 套」的**组内混用**，违背"同一关系标签下不混用替代件"的要求。

**修复**：批次3 右边界改为「容量 > rel1Sets 的各组中**最小**的容量」：
```js
var candCaps = caps.filter(function (x) { return x > rel1Sets; });
altMaxSets = candCaps.length ? Math.min.apply(null, candCaps) : rel1Sets;
```
本例 altMaxSets=32 → sets3=30 → G:1752598 整批用替代件 30 套，G:1695280 整批用主件 30 套，**不再组内混用**。
（为实现此逻辑，把原先边遍历边取 min/max 改为先收集 `caps[]` 数组再统一计算）

### 根因 2：主件库存不足仍被扣成负数（超扣）
`1717751` 在 a-us-cj **库存表无记录（=0）**，但 G:1717751 的替代件 1744181 耗尽后，引擎仍按 `sets2 * priRatio` 让主件 1717751 承担 2 套 → 消耗 2、库存 0 → **超扣**。

**修复**：`consumePrimary(qty)` 改为按实际可用量裁剪并返回实际扣减量：
```js
var availPri = isShared(pri.child) ? (t.allocated.get(pri.child)||0) : (pool.get(wh+'||'+pri.child)||{qty:0}).qty;
var take = Math.floor(Math.min(availPri, qty) / priRatio) * priRatio;
if (take <= 0) return 0;
```
调用方改为用返回值输出明细（`_p3` / `_p2`），不足的套数不扣、不展示。
