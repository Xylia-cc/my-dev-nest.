# 2026-10-15 工作日志

## 需求：BOM 关系表支持交换 B 列(子件)与 C 列(配比)

### 用户诉求
"模板导入表中的BOM关系表我需要把B列子件列和c列配比列交换一下位置"
即列序从「父件|子件|配比」改为「父件|配比|子件」。

### 调研中发现的关键 Bug（严重）
用最新模板 `组装量计算模板261015-新品.xlsx` 实测两种交换场景时**引擎直接崩溃**：

```
TypeError: Cannot read properties of undefined (reading 'push')
  at compute (engine.js:128)  ← bomSwap 检测里的 warnings.push(...)
```

**根因**：`var warnings = []` 定义在 **152 行**，而 bomSwap 自动检测在 **114~135 行**就使用了 `warnings`（128 行）。
→ 只要 BOM 表列序被判定为颠倒（正是用户要做的操作），引擎立即崩溃。

### 修复内容（engine.js）
1. **`warnings` 提前定义**：移到 `compute()` 开头（`var capByDemand` 之后），并删除原 152 行的重复定义。
2. **bomSwap 检测改用中位数比较**（原启发式不可靠）：
   - 旧逻辑：前 5 行中"子件"列都 ≤10 且"配比"列都 >100 → 判定颠倒。
     ⚠️ 缺陷：配比 >10（如 12、20）或子件编码 ≤100 时会漏判；只看前 5 行易受异常值干扰。
   - 新逻辑：取前 **50 行**采样，分别求"子件"列与"配比"列的**中位数**，若 `子件中位数 < 配比中位数`（子件编码量级本应远大于配比）→ 判定颠倒。
     ✅ 不依赖固定阈值，不受个别异常值影响。

### 结论给用户
引擎现已同时支持两种列序：
- 表头跟着一起换（B 列标题写"配比"、C 列写"子件"）→ 按表头名匹配，正常读取
- 表头不换、只换数据顺序 → 自动检测并适配（中位数比较）
两种都可直接上传，无需额外设置。
