## 规则① 改造：共享子件按「子件销量=父件日均×配比」排序分配
- 用户指令："同仓下的共享子件按子件在同仓下的销量占比大的条件优先分配共享料；ps：子件销量=父件日均*配比"。
- 引擎核心重构（engine.js `byWh.forEach` 内逻辑）：
  - **旧逻辑**：实例按「父件销量」降序统一排序，依次遍历扣减库存（顺序模型）。
  - **新逻辑（两阶段法）**：
    1. Phase 1：计算每个实例理论组装量（只读 pool，不扣减）。
    2. Phase 2：对每个共享子件，收集所有需要它的实例，按 `childSales = 父件日均 × 配比` 降序排序，依次分配库存（直接扣减 pool）。
    3. Phase 3：根据共享子件实际分配量计算实际组装量。**关键修复**：若某共享子件 allocated=0（未分到），该实例组装量被限制为 0（原 bug 导致未分配时不限制，P2 错误组装了 15 套）。
    4. Phase 4：共享子件已在 Phase 2 扣减 pool，此处只输出消耗明细；非共享子件从 pool 扣减并输出明细。
  - 关系类别批次保留：供应商组先 `processBatch`，单一组后 `processBatch`。
- 影响：同一子件在不同父件间的竞争顺序由「子件销量」决定，而非「父件销量」。典型场景：父件 A 销量高但某子件配比低，父件 B 销量低但配比高 → 该子件优先分给 B。
- 回归测试：test_engine ✅ / test_rule2 ✅ / test_rule3 ✅ / test_category ✅ 全部通过。
- UI 同步：index.html 规则① chip 改为"同仓共享子件按「子件销量=父件日均×配比」降序分配"。
